# P1600dn Series ZjStream Job Specification

The job format and protocols of the P1600dn series printers (P1606dn,
P1607dn, P1608dn, P1609dn) and the driver's behavior. Sections 1–5 describe
the print job that `rastertop1600dn` writes, section 6 the printer status
the same filter reads during the job, section 7 the toner level command
filter `commandtop1600dn`, and section 8 the PJL of the printer utility.

All multi-byte ZjStream fields are big-endian.

## 1. Job framing

| Part | Bytes |
|---|---|
| UEL | `1B 25 2D 31 32 33 34 35 58` |
| PJL | `@PJL USTATUS JOB=ON`, `@PJL USTATUS PAGE=ON`, `@PJL USTATUS DEVICE=ON`, `@PJL INFO STATUS`, `@PJL JOB NAME=<argv[3]>`, `@PJL SET DENSITY = <1..5>` (default 3), `@PJL SET JAMRECOVERY = OFF\|AUTO`, `@PJL ENTER LANGUAGE=ZJS` — each line ends in `\r\n` (`%n` in the PPD's `*cupsPJL` values) |
| Signature | `JZJZ` (no chunk header) |
| START_DOC | 28 bytes: header `size 28, type 0, items 1, reserved 12, 5A5A` + item `id 1 (DMCOLLATE), type 1, value Collate != 0` |
| pages | see 2–4 |
| END_DOC | 16 bytes: `size 16, type 1, items 0, reserved 0, 5A5A` |
| PJL trailer | UEL, `@PJL EOJ\r\n`, UEL, then (after the printer reports the end of the job, section 6) `@PJL USTATUSOFF\r\n`, UEL |

A job without raster pages produces no output. No PJL is sent between pages.

Chunk header: `u32 size` (header + items + data), `u32 type`, `u32 item count`,
`u16 reserved` = item bytes (12 per item), `u16 0x5A5A`. Item: `u32 12`,
`u16 id`, `u8 type 1`, `u8 0`, `u32 value`.

## 2. Page header

START_PAGE (type 2), items in this order:

| # | id | value |
|---|---|---|
| 1 | 3 DMPAPER | Windows paper code (wingdi.h) of PageSize in points (section 5) |
| 2 | 4 DMCOPIES | `header.NumCopies` (`*cupsManualCopies: False`) |
| 3 | 5 DMDEFAULTSOURCE | `header.MediaPosition`, 7 when 0 |
| 4 | 6 DMMEDIATYPE | `header.cupsMediaType` unchanged |
| 5 | 7 NBIE | 1 |
| 6 | 8 RESOLUTION_X | 600 |
| 7 | 9 RESOLUTION_Y | 600 |
| 8 | 12 RASTER_X | `VIDEO_X * VIDEO_BPP` |
| 9 | 13 RASTER_Y | `VIDEO_Y` |
| 10 | 16 VIDEO_BPP | `(cupsCompression & 1) + 1` |
| 11 | 17 VIDEO_X | `cupsWidth` |
| 12 | 18 VIDEO_Y | `cupsHeight` rounded up to a multiple of 12 |
| 13 | 2 DMDUPLEX | 2, only on automatic-duplex pages |
| 14 | 23 ECONOMODE | 0 or 1, always present |

No OFFSET, RET or string items are sent.

## 3. Image data

- Raster: 600 × 600 dpi, 8-bit `CUPS_CSPACE_W`; lines past `cupsHeight` are white.
- Screening: darkness `g = 255 - v`; `g == 0` stays white.
  - FastRes 1200 (2 bits per pixel): level
    `(T2[g*48 + (n % 12)*4 + (x/4) % 3] >> (6 - 2*(x & 3))) & 3`, packed
    MSB-first, where `n` is the descending line counter (rounded height on the
    first line).
  - 600 dpi (1 bit per pixel): black when `g >= T1[(n % 16)*16 + x % 16]`,
    packed MSB-first, each bit from its own pixel.
  - Tables: T2 has 12288 bytes (48 per darkness level), T1 256 bytes. The
    driver's tables are `p1600_screen_2bpp` (T2) and `p1600_screen_1bpp` (T1) in
    `src/p1600_screen_tables.h`, generated by `tools/gen_screens.py`.
- JBIG: one image per page, `Xd` = line bits rounded up to 128, `Yd = VIDEO_Y`,
  L0 128, MX 0, MY 0, order 3 (ILEAVE | SMID), options `0x5C`
  (LRLTWO | TPDON | TPBON | DPON), no ATMOVE/NEWLEN/COMMENT. The coder is
  JBIG-KIT 2.1 (`src/jbig.c`, `src/jbig_ar.c`). The driver keeps the
  trailing zero bytes of each stripe before `FF 02` (`JBG_KEEP_ZEROS`, an
  addition to JBIG-KIT); they are redundant, and the stripe decodes the same
  with or without them.
- Chunks: JBIG_BIH (type 4, 20 bytes), JBIG_BID (type 5) of exactly 65536
  bytes of stripe data each, the last zero-padded to a multiple of 4, END_JBIG
  (type 6, no items), END_PAGE (type 3, no items).

## 4. Duplex and page order

- Automatic duplex when two-sided printing is requested, the duplex unit is
  installed, DMPAPER is 1, 5, 9 or 41 and DMMEDIATYPE is 1, 258 or 282. Pages
  are sent in sheet order 2, 1, 4, 3, …; an odd last page gets a blank partner
  (2, 1, …, blank, n). Every page carries DMDUPLEX 2 (long and short edge
  alike).
- Manual duplex otherwise: even pages descending (blank first for an odd
  count), PAUSE chunk (type 11, 16 bytes, no items), odd pages ascending.
- Long-edge back sides are turned by CUPS: the PPD's `*cupsBackSide: "Rotated"`
  makes it turn them (verified with macOS `cgpdftoraster`).
- Copies: uncollated copies are DMCOPIES; collated copies arrive from CUPS as
  repeated pages.

## 5. Filter behavior in rastertop1600dn

- The blank partner page of an odd automatic-duplex job is sent in its slot
  of the last sheet (section 4) and carries the last page's settings.
- A one-page manual-duplex job is sent as that single page.
- Automatic duplex sends each sheet (back side, then front) as soon as both
  pages are encoded; the job is not spooled first. Pages are JBIG-encoded on
  several threads. The bytes and their order are those of sections 1–4.
- `@PJL JOB NAME` replaces control characters with spaces and is limited to
  80 bytes (PJL limit), cut on a UTF-8 boundary.
- Every page passes a page guard (`src/zjs_guard.c`) before it is sent.
  - The padding is forced white: the lines between `cupsHeight` and VIDEO_Y, and the bits right of RASTER_X.
  - The page must have this geometry: VIDEO_Y is a multiple of 12, within 12 lines of the content. RASTER_X = VIDEO_X × VIDEO_BPP and RASTER_Y = VIDEO_Y. The BIH has Xd = the line bits, Yd = VIDEO_Y, and the L0, order and options of section 3.
  - The framing must be that of sections 2 and 3: the START_PAGE items in section 2, BIDs of exactly 64 KiB except the last, the last padded to 4 bytes, then END_JBIG and END_PAGE.
  - The JBIG data is decoded and compared with the page, pixel by pixel.
  - A page that fails is not sent, and the job ends with an error.
- After an error, a job that already sent its header is closed with END_DOC, `@PJL EOJ` and `@PJL USTATUSOFF`. Only whole pages and whole automatic-duplex sheets have been sent at that point, so the printer finishes them and is ready again at once. A job that just stops leaves the printer waiting for the rest until its I/O timeout.
- DMPAPER comes from the driver's own table: the PPD's sizes and their landscape forms with their Windows (wingdi.h) codes. 0 is no Windows paper code and is never sent.
  - An exact match wins; otherwise a size within one point of a table entry gets that entry's code. macOS truncates PageSize, so B5 (515.9 × 728.5) arrives as 515 × 728 and still gets DMPAPER_B5 (13).
  - The PPD's 16K sizes have no wingdi.h name. They get the codes these printers receive from Windows, as seen in OpenPrinting foo2zjs captures for model `-z2`: 195 × 270 mm is 264, 184 × 260 mm is 263, and 197 × 273 mm is 257.
  - Every other size is sent as 256 (`DMPAPER_USER`).
- The PPD offers `InputSlot Auto` (MediaPosition 7), the default and the value foo2zjs and driver 3.1 sent to the P1606dn, and Manual Feed (MediaPosition 4).

## 6. Printer status during the job

The job header (section 1) asks the printer for unsolicited PJL status. The
filter reads the replies on the CUPS backchannel, fd 3, in a reader thread
(`poll(2)`, `read(2)`). The reader starts before the job header on the first
page, and only for `usb:`, `socket:`, `mdns:` and `dnssd:` device URIs when
fd 3 is open for reading. The end of the job waits for it between `@PJL EOJ`
and `@PJL USTATUSOFF`, so the printer's messages reach CUPS until the last
sheet is out.

- **Framing** (2048-byte buffer):
  - A form feed (`0x0C`) ends a message.
  - A NUL discards what precedes it.
  - `00 AC` starts a 16-byte binary block that is skipped.
  - A message longer than the buffer is dropped up to the next form feed.
- **Messages:**
  - `@PJL USTATUS DEVICE` and `@PJL INFO STATUS` carry `CODE=<n>`, which is looked up in the code table. The words may be separated by any whitespace. A message counts only when it parses fully: `CODE=` must be followed by a decimal number (0–99999).
  - `@PJL USTATUS PAGE` and `USTATUS JOB START` are only logged.
  - `USTATUS JOB END` and `USTATUS JOB CANCELED` end the wait.
- **Code table** (`src/p1600_status.c`):

| PJL code | PPD `cupsIPPReason` spec | Reason |
|---|---|---|
| 10001, 10003, 10023 | PrinterReady | (clears) |
| 40021 | CoverOpen | cover-open |
| 40120 / 40121 / 40131 | ManualDuplex | media-needed |
| 40600 | TonerMissing | toner-empty |
| 41100–41199 | ManualFeed | media-needed |
| 41002–41004 | OutOfPaper | media-empty |
| 42000 / 42002 / 42004 | InputJam | media-jam |
| 42001 / 42003 | OutputJam | media-jam |
| 42005 | DoorOpen | cover-open |
| 50003 / 50005 / 50007 | EngineFuser / EngineScanner / EngineComm | connecting-to-device |

- **Output for a listed code:**
  - `STATE: -` with the table's other reasons, each as `<reason>-error` (cover-open, media-needed, toner-empty, media-empty, media-jam, connecting-to-device; all six for PrinterReady). Reasons set by the backend stay.
  - Then `INFO: <value>` of the PPD's `cupsIPPReason <spec>` in the job language. When the PPD has no text for the code, the message is the driver's own fallback text (`src/p1600_status.c`), and the reason is still set. This affects DoorOpen, which the PPD lacks.
  - For error codes, also `STATE: +<reason>-error`.
- **Language:** the PPD keyword is `<lang>.cupsIPPReason`. The job language comes from `LC_ALL`, `LC_MESSAGES` or `LANG`, which cupsd sets for filters; `nb` and `nn` become `no`. The lookup is `ll_CC.`, then `ll.`, then the base keyword, per entry. English, `C` and `POSIX` use the base keyword.
- **Unlisted codes** print nothing but a `DEBUG:` line.
- **Page progress:**
  - After each screened line `n` (counting down from the rounded page height `H`), the filter prints `INFO: <Printingpage text> <page>, <(H-n+1)*100/H>% <Complete text>...` when `(n - 1) % 256 == 0`.
  - The texts are the translation strings of `cupsIPPReason Printingpage` and `Complete`.
- **Status monitor:** the PPD has no `*APStatusMonitorPath`, so no status-monitor socket (127.0.0.1:8080) is used; status reaches CUPS through the filter's messages only.
- **End of the wait** for `USTATUS JOB END`:
  - 15 s after the job data when the printer has not answered at all.
  - 10 min after the last message otherwise. This leaves time to turn a manual-duplex stack.
  - It also ends when the backend closes the backchannel.

## 7. Toner level command filter (LEDM)

The PPD routes `*cupsCommands: "ReportLevels PrintSelfTestPage Clean"` jobs
through `*cupsFilter: "application/vnd.cups-command 100 .../commandtop1600dn"`
(`src/commandtop1600dn.c`, `src/p1600_supplies.c`, `src/p1600_usb_ledm.c`; USB
through IOKit's `IOUSBInterfaceInterface300`). The toner level query uses no
PJL.

- **Input:** the command file (argv[6] or stdin) is read with `cupsFileGetConf`. Each `ReportLevels` line, case-insensitive, triggers one query. `PrintSelfTestPage` and `Clean` send the utility's Configuration Page and Cleaning Page PJL (section 8) to the printer through the queue. Other commands are logged.
- **`usb:` device URIs:**
  - **Device lookup:** macOS USB URIs have the form `usb://<make>/<product>?serial=<serial>`, while the device's `USB Product Name` is `<make> <product>`. The device is the one whose `USB Serial Number` equals the URI's `serial=` value; further query parameters (`&interface=1`) are ignored. Its `USB Product Name` must equal the URI product, with or without the make prefix and in any letter case; a matching serial number identifies a vendor `03F0` device on its own. A URI without a serial is matched by the product alone.
  - **Interface:** the first interface with class `FF`, subclass `02`, protocol `10`, with its first bulk OUT and first bulk IN pipes.
  - **Request:** the 49 bytes `GET /DevMgmt/ConsumableConfigDyn.xml HTTP/1.1\r\n\r\n` (no Host header).
  - **Response:** an HTTP response (Content-Length or chunked), read with 1 s timeouts. The status must be 200. The body limit is 256 KiB.
  - **Level:** the first `<dd:ConsumablePercentageLevelRemaining>` (0–100).
- **Other URIs:** the filter runs `/System/Library/Printers/Libraries/snmpInk <queue>` without a shell (`posix_spawn`) and with a 30 s limit. The level is the first `prtMarkerSuppliesLevel` of the Printer MIB plist it prints, scaled by `prtMarkerSuppliesMaxCapacity` when that is known.
- **Output:** one `ATTR: marker-colors=#000000 marker-levels=<n> marker-names=Black marker-types=toner` line when a level (0–100) was found. The exit status is 0.

## 8. Printer utility

`P1600dn Series Utility.app` and the command-line `p1600dn-utility`
(`src/p1600_utility.c`, `src/p1600_ews_proxy.c`, `utility/`) are the printer
utility, native arm64. The PPD's `*APPrinterUtilityPath` names the app. macOS
opens it with an Open Application event whose `'prdt'` parameter is the CUPS
queue name. Launched without `'prdt'`, it opens a window with a printer
picker. The window is localized in 16 languages.

### Transport

- **USB** (`usb:` device URIs): the device comes from the queue's device URI (serial number, matched as in section 7), not from the queue name, so a renamed queue still works. The series (`P1600dn`…`P1609dn`) has USB vendor ID `0x03F0` and product ID `0x0A2A`.
  - The utility opens the printer interface, class 7, subclass 1, any protocol, exclusively. While another program (such as a print job) holds it, it tries up to 10 times, 1 s apart.
  - Writes time out after 5 s. A read that fails or times out clears the IN pipe's stall.
- **Network** (`socket:`, `lpd:`, `ipp:`, `ipps:`, `http:`, `https:`, `dnssd:`, `mdns:`): the utility connects to the AppSocket port 9100 (or the port of a `socket:` URI), where PJL INQUIRE replies return on the same connection. Bonjour services are resolved through DNS-SD.

### Commands

Every command is one write in its own session: `ESC %-12345X`, the PJL lines each ending in LF (no CR), `ESC %-12345X`. There is no JOB/EOJ wrapper.

| Control | Values | Bytes |
|---|---|---|
| Sleep after | 1, 5, 15, 30, 60, 120 min (the value table also holds 0) | `@PJL SET POWERSAVETIME=n` |
| Auto Off after | Never (0), 30, 60, 120, 240, 480, 1440 min | `@PJL SET INACTIVEOFFTIME=n` |
| Quiet Mode | Enable / Disable | `@PJL SET QUIETMODE=ON` / `OFF` |
| Demo, Configuration, Supply Status page | — | `@PJL SET LANG=<l>` LF `@PJL SET TESTPAGE=DEMOPAGE` / `SELFTEST` / `SUPPLIES` |
| Cleaning Page (after the instruction panel) | — | `@PJL CLEANPRINTER` |
| Read at window load | — | `@PJL INQUIRE POWERSAVETIME` / `INACTIVEOFFTIME` / `QUIETMODE`; reply `@PJL INQUIRE <VAR>` CR LF `<value>` CR LF FF |

- **Reading**: the three INQUIREs are sent in this order, each in its own session.
  - Replies are collected for up to 2 s.
  - The reply may arrive in pieces and after other output.
  - A form feed ends the value.
- **Unread or unknown values** are shown as "—" and never written.
- **Writing**: a setting is sent alone when it is changed, and only when its new value differs from the value read. An information page is sent when its Print button is pressed.
- **LANG** is the PJL name of the window's language: DANISH, GERMAN, ENGLISH, SPANISH, FINNISH, FRENCH, ITALIAN, KOREAN, DUTCH, NORWEGIAN (`no`, `nb`, `nn`), PORTUGUESE, SWEDISH, TURKISH, CHINESE (`zh`), TCHINESE (`zh_TW`, `zh_HK`, `zh-Hant`). Any other language gets ENGLISH.
- **CUPS commands**: `PrintSelfTestPage` and `Clean` are also available as CUPS commands (`commandtop1600dn`, section 7). They reach the printer through the queue, so they work while a job holds the USB interface.

### Printer web pages

- **USB printers**: the web pages are served over USB interface FF/02/10 (HTTP, as in section 7).
  - A proxy inside the utility listens on a system-chosen loopback port (127.0.0.1) and the utility opens `/SSI/index.htm` there.
  - One request at a time; responses are re-framed with Content-Length and `Connection: close`.
  - A failed printer exchange answers 502.
  - The proxy ends after 180 s idle.
- **Network printers**: the utility opens `http://<address>/`.
